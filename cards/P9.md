# P9: MCP server over the scored accounts, with trajectory evals

Model: Sonnet 5.5. Day 5, second half. Optional. If time is short, skip
it; the submission is complete without it. It exists because the job
description lists "the harness agents run inside: tool calling, MCP
servers, eval suites", and the read API is already there.

## Goal

`uv run sis mcp` starts an MCP server exposing the same read operations
as the API as tools, so a salesperson's agent (or Claude Desktop) can ask
"show me untouched healthcare accounts in Australia with an expired
certificate" and get grounded answers. 10 scripted multi-turn
trajectories run as an eval and assert tool-call correctness.

## Read first

DESIGN.md sections 2 and 10. P5's `routes.py` and `schemas.py`. P8's
report card endpoint.

## Depends on

P5. P7 and P8 improve it but are not required.

## Outputs

```
sis/mcp/server.py           FastMCP (mcp python sdk) server, stdio and streamable-http transports.
                            Tools, each with a pydantic input model and a bounded output:
                              search_accounts(q?, segment?, country?, industry?, min_exposure?, has_signal?, sort?, limit<=50)

evals/mcp/trajectories.yaml 10 scripted conversations: user turns, expected tool sequence (names and key args),
                            and an assertion on the final answer (must mention N entity names that exist in the

                            bounded to 8 tool calls per trajectory), records the trace to evals/mcp/traces/<n>.json,
```

## Steps

1. Refactor P5 routes to call `sis/api/service.py`; tests still pass.
2. Implement the server; run it with stdio and connect from Claude
   Desktop or the MCP inspector; call each tool once by hand.
3. Write the 10 trajectories. Include at least: a pure filter query, a
   query needing 2 tools (search then get_account), a query where the
   right answer is "none found", a query asking for evidence, a query
   asking for a report card that does not exist yet, and a query trying to
   get the agent to invent an industry for an unclassified account (the
   assertion: it must say unclassified).
4. Run the eval 3 times; report per-trajectory results and variance.
   Threshold: 9 of 10 pass on grounding in every run; task success
   reported without a threshold.
5. Report `docs/MCP_REPORT.md` with the table, 1 full trace, cost per
   trajectory, and what the harness does not yet have (human checkpoints,
   replay from trace) with 1 line each on how it would be added.
