# P7: What does this business do (LLM classifier, evaluated and costed)

Model: Sonnet 5.5 for the build. The classifier runs on the `errand`
tier of the model gateway (config/llm_tiers.yaml); this card also builds
the gateway itself. Day 4, second half.

## Goal

`uv run sis classify --top N` fills `entity_profile` for the top N
entities by priority with `{is_business, industry, description,
confidence}`, cached by input hash, with every call logged with tokens
and USD. `uv run pytest -m llm` runs the labelled-set evaluation and
reports accuracy. DESIGN.md section 7.2 gets its numbers from here.

## Read first

DESIGN.md section 7 in full. DATA_MODEL.md sections 5.1 and 5.3.
`config/industry_taxonomy.yaml` from P0.

## Depends on

P3 (priority), P5 (the field shows in the UI once present; P5 already
left-joins `entity_profile`).

## Inputs

For each entity: `display_name`, up to 5 distinct `http_title`, up to 3
`cert_subject_o`, union of `http_components` (max 20), up to 3 distinct
`http_server`, up to 5 hostnames, country, and the first 600 characters of
the body part of `data` from up to 2 HTTP banners (the body is whatever
follows the first blank line in `data`; strip tags with a regex; collapse
whitespace). Total input capped at 2,500 characters of content.

## Steps

1. **Input builder** exactly as the Inputs section. Deterministic
   ordering (sort titles by frequency then text) so the hash is stable.
2. **Labelled set.** Sample 200 entities from the top 5,000 by priority
   with seed 23, stratified 50 per segment. The builder labels them by
   reading the same inputs the model sees (a small CLI `sis classify
   --label` that shows the inputs and asks for industry and is_business).
   Budget 90 minutes. Record `labelled_at`. Then re-label 50 of them (seed
   29) in a second pass at least 1 hour later without looking at the first
   answers; store as `labels_relabel.jsonl`. Agreement between passes is
   the label-noise ceiling and goes in the report.
3. **Prompt.** Write it. Few-shot: 3 examples taken from the labelled set
   (and excluded from the evaluation).
4. **Evaluation, per model, across tiers**: run the same 197 through
   each `errand` model and the primary `mid` model, with the gateway's
   `tier_override` and cache disabled, escalation off. Report per model:
   industry accuracy, macro F1, `is_business` precision and recall, schema
   failure rate, mean confidence on correct vs incorrect, cost per entity,
   rate-limit hits, latency p50/p95. Then run once more through the
   gateway as configured (errand with escalation on) and report the same
   plus the escalation rate. This is the evidence that the errand tier is
   the right tier for this task: ship on the errand tier when its primary
   reaches industry accuracy >= 0.80 and `is_business` recall >= 0.90 with
   schema failures <= 2 percent; otherwise reorder the errand list or move
   the task to `mid` in `llm_tiers.yaml` and say why in the report. Below
   threshold: iterate the prompt at most 3 times (bump PROMPT_VERSION each
   time, keep every result file), and if still below, ship with the field
   labelled "unclassified (below threshold)" in the UI and say so in the
   report.
5. **Run** on top N = `CLASSIFY_TOP_N` (5,000). Dry-run first and print
   the token estimate and projected cost against the errand tier budget.
   If the projection exceeds it, STOP and report the projection; the
   human tops up OpenRouter credit. Do not lower N to save credit: the
   quality thresholds are fixed and the budget is a ceiling that asks for
   more money, not a reason to shrink the deliverable. The tier budgets in
   `llm_tiers.yaml` split the credit on hand (8 USD now, up to 12 USD
   with a top-up).
6. **Report** `docs/CLASSIFY_REPORT.md`: the metrics, 10 correct and 10
   incorrect examples with inputs, the confusion pairs that dominate,
   total cost, cost per entity, cache hit rate on a second run (must be
   100 percent). Copy cost per entity and accuracy into DESIGN.md section
   7.2.
7. **Export** again so the bundle carries the profile; the accounts page
   filter `industry` becomes active.

## Acceptance tests

```
uv run pytest tests/test_classify.py -q           # prompt builder deterministic; schema rejects industry outside taxonomy
uv run pytest tests/test_classify.py -m llm -q    # 5 live calls succeed, llm_calls has 5 rows with cost > 0, second run 5 cache hits
uv run sis classify --top 50 --dry-run             # prints 3 prompts and an estimate
uv run python evals/industry/run.py               # results.json with accuracy >= 0.80 or a documented shortfall
uv run sis classify --top 5000                     # completes under budget; entity_profile has 5000 rows
```

## Does NOT do

- No web fetching of the prospect's site. Inputs are only what the scan
  already captured.
- No classification beyond top N; the rest show no industry.
- No use of the profile in scoring. It is a filter and a display field.
- No provider-specific SDK. Everything goes through the gateway.
- No people, revenue, or headcount guesses. The schema has no such
  fields on purpose.
