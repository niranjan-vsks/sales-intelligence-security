# P4: Evaluation harness, in CI

Model: Opus 5.5. Day 3, first half. The metrics are simple; the honesty
in how they are reported is the deliverable.

## Goal

`uv run sis evaluate <file_id>` writes `labels.parquet`, `metrics.json`,
`ablations.json`, `baselines.json` per DATA_MODEL.md section 7, and
`uv run pytest -m eval` recomputes the headline metric on a committed
fixture and fails below a threshold. DESIGN.md section 6 gets its numbers
from this card.

## Read first

DESIGN.md section 6. DATA_MODEL.md sections 3.1 (held-out list) and 7.
findings/07_ground_truth.md. findings/queries/07c_ground_truth.py.

## Depends on

P3.

## Inputs

`banners`, `vulns`, `banner_entity`, `entities`, `signals`, `scores` for
the file. `config/scoring.yaml`.

## Outputs

```
sis/evaluate/labels.py      build_labels(file_id) -> labels.parquet
sis/evaluate/metrics.py     precision_at_k, lift_at_k, rank_biserial; evaluate(file_id) -> metrics.json
sis/evaluate/ablation.py    rescore with each fact weight set to 0 (via a scoring override, not by editing yaml),
                            then metrics -> ablations.json
sis/evaluate/baselines.py   random (seeded, 5 draws averaged), breadth_only (rank by n_modules desc),
                            cve_count_only (rank by A_inferred_cves desc) -> baselines.json
sis/evaluate/report.py      renders docs/EVAL_REPORT_<file_id>.md with every table
sis/cli.py                  `sis evaluate FILE_ID`
tests/fixtures/eval_bundle/   50,000 active entities sampled with seed 11 from the real scores + labels
                              (entity_id, priority, exposure, segment, fact_a..d, all labels). Under 10 MB.
tests/test_eval.py          marked `eval`: recompute precision@1000 on the fixture; assert >= committed value
evals/README.md             what each label is, what it cannot say, how to add a 7th label (the UI feedback)
.github/workflows/ci.yml    the eval step no longer `continue-on-error`
```

## Steps

1. **Labels** at entity grain, from the full `vulns` and `banners` (not
   `vulns_clean`):
   - `label_kev`: any banner of the entity has a vulns row with `kev = true`
     (join `vulns.id = banners.id`; `ransomware_campaign` is
     `json_extract_string(other_keys, '$.ransomware_campaign')`, reported
     as a 7th informational label `label_ransomware`)
   - `label_verified`: any row with `verified = true`
   - `label_heartbleed`: any banner with `opts_heartbleed` containing `VULNERABLE`
   - `label_opts_vulns`: any banner with `len(opts_vulns) > 0`
   - `label_any_tested`: verified or heartbleed or opts_vulns
   - `label_has_vendor`: any `D_waf` or `D_security_appliance` signal
   Record counts and base rates per label (base rate = share of active
   entities with the label).
2. **Metrics** for the ranking by `priority` (ties by entity_id) and,
   separately, by `exposure`:
   - precision@k for k in (100, 1000, 10000) per label
   - lift@k = precision@k / base rate
   - rank-biserial: `2 * AUC - 1` where AUC is computed with DuckDB from
     the ranks of positives (Mann-Whitney), no sklearn
   - restrict a second pass to the `untouched` segment only, since that
     is the list sales will actually call
3. **Confidence intervals** for precision@k: Wilson interval at 95
   percent. Report them. For label_any_tested the intervals will be wide;
   that is the point.
4. **Baselines**: random (expected precision = base rate; also run 5
   seeded shuffles and report the mean), breadth_only, cve_count_only.
   Note in the report that cve_count_only is almost fact A alone, so if
   the full model does not beat it on the tested labels, say so plainly.
5. **Ablations**: for each fact in (a, b, c), rescore with that exposure
   weight set to 0 and the others renormalised to sum to 1; recompute
   metrics. Also ablate D by forcing every segment to `untouched`.
6. **Sanity**: `label_has_vendor` rate in `displace` must be 1.0 by
   construction; report it anyway together with its rate in the other 3
   segments and the exposure quantiles of `displace` vs `untouched`.
7. **Fixture**: sample 50,000 active entities (seed 11), write
   `tests/fixtures/eval_bundle/`. Compute precision@1000 on
   `label_any_tested` and on `label_kev` from the fixture; commit those 2
   numbers in `tests/eval_thresholds.json` as `{metric: value * 0.95}`.
8. **Report** `docs/EVAL_REPORT_<file_id>.md`: 1 table per label with
   full model, 3 baselines and 4 ablations as rows and precision@k (with
   CI), lift@k, rank-biserial as columns. A short "what this does and does
   not show" paragraph using the wording in DESIGN.md section 6. Copy the
   headline numbers into DESIGN.md section 6 where `[P4 fills]` appears.
9. CI: remove `continue-on-error` from the eval job.

## Acceptance tests

```
uv run pytest tests/test_eval.py -m eval -q
  test_precision_at_k_hand:       5-row synthetic ranking -> known precision values
  test_rank_biserial_hand:        perfect ranking -> 1.0; reversed -> -1.0; random large -> within 0.05 of 0
  test_wilson_interval:           known case from a textbook example
  test_fixture_threshold:         precision@1000 on label_any_tested and label_kev >= committed thresholds
uv run sis evaluate <file_id>    # metrics.json, ablations.json, baselines.json, EVAL_REPORT written
cat $SIS_DATA/<file_id>/eval/metrics.json | python -m json.tool | head   # keys: labels, by_priority, by_exposure, untouched_only
```

## Does NOT do

- No fitting of weights to labels. If the ablation shows a fact hurts,
  the report says so and the architect decides; this card does not change
  `scoring.yaml`.
- No human labelling. The 7th label (UI feedback) is described in
  evals/README.md and not populated.
- No LLM.
