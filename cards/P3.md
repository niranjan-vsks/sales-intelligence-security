# P3: Signals, evidence, scores

Model: Opus 5.5. Day 2, second half. The formulas are fixed; the
judgement is in getting the held-out exclusion and the peer ranks exactly
right.

## Goal

`uv run sis score <file_id>` produces `signals`, `evidence` and `scores`
for 1 file per DATA_MODEL.md section 3 and DESIGN.md section 5, and
`uv run sis score --merge` rebuilds `$SIS_DATA/current/scores.parquet`.
Every number is reproducible from `config/scoring.yaml` and the Parquet.

## Read first

DESIGN.md section 5 in full. DATA_MODEL.md section 3. The signal
catalogue table is the contract. findings/07_what_we_sell_map.csv (the
exact predicates for W01 to W07, P01 to P03). findings/08_candidates.md
for what each signal means. findings/queries/07_signals.py and
07b_negative.py (working SQL for the predicates; reuse).

## Depends on

P2 (needs `banner_entity`, `entities`).

## Facts from the P1 and P2 builds that change this card

- The vulns table columns are `id` (not `banner_id`), `cvss_version`
  DOUBLE, and `ransomware_campaign` is inside the `other_keys` JSON:
  `json_extract_string(other_keys, '$.ransomware_campaign')`. See
  DATA_MODEL 1.2 as corrected.
- `file_id` is `<sha256>-<bytes>`; the real one is in tasks/state.md.
- Banners has 93 columns plus `file_id`.
- **Edge banners.** P2's eyeball check found tenants behind a shared
  Incapsula edge (myverobc.com, superyacht.me) whose banners describe the
  edge. Rule, now in DESIGN 5.5: a banner is an edge banner when
  `list_contains(tags, 'cdn')` or `http_waf` matches mapping W01. Edge
  banners feed only `D_waf`, `D_edge_substitute` and `C_live_web`. They
  are excluded from every A, B and other C signal and from
  `C_breadth_modules` / `C_breadth_ports`. Add a test with 1 entity whose
  banners are all edge banners: fact_a = fact_b = 0, fact_c comes from
  C_live_web only, fact_d = 1, segment = displace.

## Steps

1. **Entity banners view.** `eb` = banners joined to banner_entity, for
   active entities only. All signal SQL runs over `eb` grouped by
   `entity_id`.
2. **Held-out exclusion.** Build `vulns_clean` = vulns where
   `coalesce(kev, false) = false AND coalesce(verified, false) = false`
   (join on `vulns.id = banners.id`). `A_inferred_cves`
   = max over the entity's banners of `count(*)` in `vulns_clean` per
   banner; `A_max_cvss` = max `cvss` from `vulns_clean`. Do not read
   `n_vulns` or `max_cvss` from the banner row for scoring. Assert in a
   test that an entity whose only CVEs are kev gets `A_inferred_cves = 0`.
3. **Signals.** Implement every row of the catalogue as 1 SQL expression
   in `catalogue.py`. Generate the signals table from the catalogue, not
   by hand per signal. `B_legacy_tls`: `ssl_versions` elements are strings
   like `-SSLv3` (not offered) or `TLSv1.2` (offered); treat an element
   as offered only when it has no leading `-`.
4. **Peer groups.** `breadth_bucket` from `n_modules` using
   `scoring.yaml peer.breadth_buckets`; `peer_group = country_code || '|'
   || bucket`; groups with fewer than `PEER_MIN_SIZE` active entities fall
   back to `'*|' || bucket`, then `'*|*'`. Write back to `entities`.
5. **Percent ranks.** For `kind in ('count','max','ratio')` signals,
   `pct_in_peer = percent_rank() OVER (PARTITION BY peer_group ORDER BY
   value)`, computed over entities that have the signal; entities without
   it get no row (pct = 0 in the formula).
6. **Fact scores and exposure** exactly as DESIGN.md 5.2, constants read
   from `scoring.yaml`, never literals in code. Implement as 1 SQL
   statement per fact over a pivoted signals table; keep it readable.
7. **Segments and priority** exactly as DESIGN.md 5.3.
8. **Ranks.** `rank_overall` by `priority desc, exposure desc, entity_id`
   (deterministic ties). `rank_in_segment`, `rank_in_country` likewise.
9. **top_signals.** Contribution of each signal = its term in the fact
   formula times the fact's exposure weight times 100; take the top 5 by
   contribution, ties by signal_id. Store as a list.
10. **Evidence.** For every (entity, signal) row, the up to 5 banners per
    DATA_MODEL 3.2. `value` is the firing value as text: the waf name, the
    cpe string, the cert expiry date, the module name, the count. `snippet`
    = first 300 chars of `data` with `\r\n` collapsed to ` | `.
11. **merge_current**: latest file's scores per entity; `rank_*`
    recomputed over the merged set.
12. **Report** `docs/SCORE_REPORT_<file_id>.md`: entity counts per
    segment; exposure quantiles per segment; signal fire rates (entities
    with each signal, percent); top 20 entities by priority with their
    top_signals; 10 random `untouched` entities with evidence (seed 7),
    each with a 1-line "does this look like a real prospect" judgement;
    the peer-group size distribution and how many entities fell back.
13. **Sanity assertions** written as tests on the real output: the
    `displace` segment has `D_waf or D_security_appliance` on 100 percent
    of its entities; `untouched` has 0 percent of W01 to W07; every
    `exposure` is in [0, 100]; `fact_*` in [0, 1]; the Stage 1 target group
    (prerequisite, no sell, no substitute) size is within 5 percent of
    131,104 when computed with the same predicates (differences come from
    fallback entities; report the number).

## Acceptance tests

```
uv run pytest tests/test_signals.py tests/test_scoring.py -q
  test_catalogue_matches_data_model:  signal ids == the 22 in DATA_MODEL 3.1
  test_heldout_excluded:              synthetic vulns with kev only -> A_inferred_cves 0
  test_legacy_tls_parsing:            ['-SSLv3','TLSv1.2'] -> 0; ['SSLv3'] -> 1
  test_fact_formulas:                 hand-computed fact_a/b/c/d for 3 synthetic entities match to 1e-9
  test_segments:                      4 synthetic entities land in the 4 segments
  test_peer_fallback:                 a country with 5 entities falls back to '*|bucket'
  test_rank_deterministic:            same input twice -> identical scores.parquet bytes
  test_evidence_cap:                  an entity with 20 firing banners -> 5 evidence rows per signal
uv run sis score <file_id>      # completes; SCORE_REPORT written
uv run sis score --merge        # current/scores.parquet exists
```

## Does NOT do

- No evaluation metrics (P4).
- No LLM, no text parsing beyond the stored snippet.
- No changes to weights without bumping `scoring_version`.
- Does not score blocked entities.
- Does not use `org`, `asn`, `isp`, city, lat/long, or any `*-rat`
  module.
