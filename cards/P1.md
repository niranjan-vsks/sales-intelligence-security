# P1: Ingestion, idempotent and malformed-safe

Model: Sonnet 5.5. Day 1, second half. The flattener already exists; this
card productionises it.

## Goal

`uv run sis ingest <path>` turns 1 raw delivery into
`$SIS_DATA/<file_id>/banners/`, `$SIS_DATA/<file_id>/vulns/` and an
`ingest_log` row, atomically, skipping duplicates, quarantining garbage,
and reporting throughput numbers that DESIGN.md section 8 needs.

## Steps

1. Move `01_flatten.py` logic into `sis/ingest/flatten.py` without
   changing output columns. Add `file_id`. Keep the vulns child-row
   emission. Keep the `extra_json` stash of unknown top-level blocks.
2. `compute_file_id`: read the first 64 MiB, sha256, append the byte
   length. Must take under 5 seconds on the 16.4 GB file.
3. Pre-flight, before any output: magic bytes must be zstd
   (`28 b5 2f fd`) else `rejected`. Decompress the first 1,000 lines; if
   more than 10 fail JSON parse or lack `_shodan.id`, status `quarantined`,
   write nothing but the log row and copy the first 50 bad lines to
   `$SIS_DATA/quarantine/<file_id>.txt`.
4. Duplicate check: if `ingest_log` has `status = 'ok'` for this
   `file_id` and `--force` is absent, log `duplicate`, exit 0, print the
   earlier run's numbers.
5. Run: output to `$SIS_DATA/<file_id>.tmp/`. Workers as in the explorer's
   run (multiprocessing, line ranges or a shared queue, 100,000-row
   batches, pyarrow writer, zstd Parquet). Each worker counts
   `lines_read`, `rows_written`, `rows_dropped` by reason.
6. Reconcile: `lines_read == rows_written + rows_dropped` or fail. Count
   rows in the written Parquet with DuckDB and require equality with
   `rows_written`. Then rename `.tmp` to final. On any failure, delete
   `.tmp` and log `failed` with the error.
7. Key inventory: while flattening, count top-level keys seen per file
   (the explorer did this; keep it). Write to
   `$SIS_DATA/<file_id>/key_inventory.json`. Print any key not in the
   known list as "new provider field".
8. Write `docs/INGEST_REPORT_<file_id>.md`: byte length, lines read, rows
   written, dropped by reason, vuln rows, wall seconds, lines per second,
   MB per second compressed, Parquet bytes out, workers, machine (CPU
   count, RAM). These are the numbers DESIGN.md section 8 cites.
9. Equivalence with the explorer's run: `count(*)` of new banners equals
   14,608,406; `count(*)` of vulns equals 20,988,468; and
   `SELECT md5(string_agg(id, ',' ORDER BY id))` over new banners equals the
   same over `$SIS_DATA/full/banners/*.parquet`. If the hashes differ, the
   card is not done.

## Does NOT do

- No entity resolution, no scoring.
- Does not change the flattened schema. A new column is a P-later change
  with a pipeline_version bump.
- Does not delete or modify `$SIS_DATA/full/`.
- Does not parallelise across files; 1 file per invocation. Multi-file
  orchestration is described in DESIGN.md section 8 and not built.
