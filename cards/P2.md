# P2: Entity resolution

Model: Opus 5.5. Day 2, first half. This is the step most submissions get
wrong, and the rules have edge cases that need judgement while coding.

## Goal

`uv run sis resolve <file_id>` produces `banner_entity`, `entities` and
`unattributed_summary` for 1 file, and `uv run sis resolve --merge`
rebuilds `$SIS_DATA/current/entities.parquet` from all ingested files.
485,089 entities on the real file by the primary key, plus whatever the
fallbacks add, with blocked entities marked and operator zones excluded.

## Steps

1. **Candidate names per banner.** Build a temp table
   `names(banner_id, name, kind)` with kind in (`domain`, `cert_cn`,
   `http_host`):
   - `domain`: each element of `domains`, normalised.
   - `cert_cn`: `registered_domain(cert_subject_cn)` and
     `registered_domain(x)` for each `cert_san` element; drop wildcards
     (`*.`) before extracting; drop names that fail normalisation.
   - `http_host`: `registered_domain(http_host)` when `http_host` is not an
     IPv4/IPv6 literal and not equal to the banner's own ip.
2. **IP coverage per name**, computed per kind:
   `coverage(name, kind) = count(distinct coalesce(ip_str, ipv6))`.
3. **Operator list.** Union `config/operator_domains.txt` with every
   `domain`-kind name whose coverage is above `ROLLUP_MAX_IPS`. Write the
   data-derived additions back to `config/operator_domains.txt` under a
   `# derived from <file_id>` header, sorted, deduplicated. Any name in the
   operator list is excluded from every kind.
4. **Primary attribution.** `banner_entity` rows with `key_kind='domain'`,
   `attribution='primary'` for every (banner, domain) where coverage
   `<= ROLLUP_MAX_IPS` and not an operator.
5. **Fallback attribution.** For banners with 0 primary rows: `cert_cn`
   names first, then `http_host` names, same coverage rule, same operator
   exclusion. A banner takes fallback rows from only the first kind that
   yields any. `attribution='fallback'`.
6. **entity_id** = sha1 of `key_kind || ':' || key_value`. Note: the same
   domain reached by `domain` and by `cert_cn` yields different entity
   ids by this rule. Resolve that: if a `key_value` exists as a `domain`
   kind anywhere in the file, fallback rows for the same value are
   re-keyed to the `domain` kind. Do this before hashing.
7. **entities** per DATA_MODEL 2.2. `blocked_reason`: `honeypot_or_scanner`
   if any banner matches B01; `c2_or_malware` if any matches B02; both
   present, prefer `c2_or_malware`. `peer_group` is computed by P3; leave
   null here.
8. **unattributed_summary**: `no_name` = `len(domains)=0` and no fallback
   name; `operator_only` = every name is an operator; `over_cutoff` =
   names exist but all exceed the cutoff and are not in the operator list
   (should be 0 after step 3, assert it); `blocked` = attributed but the
   entity is blocked.
9. **merge_current**: union of all `entities.parquet` across files with
   `status = 'ok'` in `ingest_log`; group by `entity_id`; `first_seen_file`
   = min by `received_at`, `last_seen_file` = max; counts and modes from
   the latest file only; `status` blocked if blocked in the latest file.
10. **Report** `docs/RESOLVE_REPORT_<file_id>.md`: entities by key_kind;
    banners attributed primary / fallback / none; unattributed by reason;
    blocked by reason; top 20 entities by n_banners (eyeball for operators
    that slipped through: if any of the top 20 looks like a hosting
    provider, add it to operator_domains.txt and rerun; record what was
    added); distribution of n_banners per entity (p50, p90, p99, max).
11. **Eyeball check**, required: print 20 random entities with their
    banners (seed 7) to the report and state in 1 line each whether the
    grouping looks right. This is the same check the explorer did; it
    must be repeated after the fallbacks.

## Does NOT do

- No scoring, no signals, no peer groups.
- No `org`-based entities (self-hosting organisations). Noted in
  DESIGN.md section 4 as a second roll-up not built.
- No network calls (tldextract must use its bundled list).
- No deletion of entities on merge; unseen entities keep their
  `last_seen_file`.
