# P5: Export bundle, FastAPI, minimal UI, deploy

Model: Sonnet 5.5. Day 3, second half, into day 4 morning. After P5 the
submission is complete: hosted link, ranked accounts, evidence, write-up
numbers in place.

## Goal

`uv run sis export` builds the serve bundle. `uv run sis serve` runs a
FastAPI app over it with 5 JSON endpoints and 3 HTML pages. The app is
deployed to Fly.io and reachable by link. Every request is traced with
Logfire. UI is deliberately minimal: find, filter, sort, open, read
evidence, mark feedback.

## Read first

DESIGN.md sections 2, 9, 11. DATA_MODEL.md section 6. The job
description's stack: FastAPI, Pydantic, Logfire.

## Depends on

P3 (scores). P4 is not required for the app but its numbers go into the
About page; use placeholders if P4 is not done.

## Inputs

`$SIS_DATA/current/entities.parquet`, `current/scores.parquet`, the
latest file's `signals.parquet`, `evidence.parquet`. `entity_profile`
and `events` if present (P6, P7), else empty tables with the right schema.

## Steps

1. **Export.** Build the 4 Parquet files and `bundle.json`. Evidence rows
   only for active entities. Sort accounts by `rank_overall` so the first
   row group is the first page. Print bundle size; it must be under 800 MB
   or the card stops and reports (then cap evidence to 3 per signal and
   retry).
2. **App.** Lifespan: connect DuckDB read-only, `CREATE VIEW` per file,
   keep the connection on `app.state`. 1 connection, requests serialised
   through a lock; concurrency is not a goal at this size. Set
   `memory_limit` to 512 MB.
3. **Routes** per the list. Filters compose with AND. Unknown `sort`
   values return 422. `q` is applied with a parameter, never string
   formatting into SQL.
4. **Detail page.** Sections in this order: header (name, segment,
   exposure, priority, rank, peer group, country, operator, industry +
   description if present), "Why" (top_signals with contribution and plain
   label from a `SIGNAL_LABELS` dict), "Evidence" (per signal: ip, port,
   module, field, value, snippet, observed_at), "Protection present" (the
   D signals with the vendor value), "Changes" (events, if any), and 2
   buttons: Mark prospect, Not a fit. Buttons POST feedback via htmx and
   swap to a confirmation.
5. **Accounts page.** Filters as form fields; results table with columns
   name, segment, exposure, priority, country, n_banners, top signal,
   industry; 50 per page; htmx `hx-get` for paging. Default sort
   `priority desc`, default segment filter `untouched`.
6. **About page.** Renders DESIGN.md sections 1, 5, 6, 7 as HTML
   (markdown library) so the reviewer reads the write-up next to the
   data. Footer on every page: bundle version, scoring version,
   `ROLLUP_MAX_IPS`, number of accounts.
7. **Logfire.** `logfire.instrument_fastapi(app)`; every DuckDB query
   inside `logfire.span('query', sql=...)`. Without a token, console
   output only.
8. **Container and deploy.** Build locally, run, hit `/api/health`. Deploy
   with `fly launch` and `fly deploy`. Record the live URL and the exact
   cost from the pricing page in `docs/DEPLOY.md` and in DESIGN.md
   section 9 where `[P5 fills]` appears. If Fly fails for any reason after
   2 attempts, deploy to Render free and record that instead.
9. **Smoke on the live URL**: `/api/health` 200; `/api/accounts?segment=untouched`
   returns 50 items; open 1 detail page; POST 1 feedback; confirm
   feedback.jsonl grew (via `fly ssh console` or an admin endpoint guarded
   by a token).

```
uv run pytest tests/test_api.py -q

curl localhost:8000/api/health                     # 200, bundle_version present
curl "localhost:8000/api/accounts?segment=untouched&page_size=5"   # 5 items, sorted by priority desc
<live url>/api/health                              # 200
```

## Does NOT do

- No authentication (the link is the share mechanism; say so in DEPLOY.md).
- No email drafting, no export to CSV, no charts, no client-side framework.
- No writes to the pipeline tables; feedback goes to a JSONL file only.
- No report card generation (P8 adds a button and endpoint).
- No Postgres.
