# Lessons

- The brief said the assignment was pasted but it was not. Flag missing inputs up front and mark everything derived from a paraphrase as an assumption.

- 2026-11-02: User asked "why Anthropic?" and I started rewriting 5 spec files before answering fully. Rule: a why question gets an answer and a proposal. Specs change only after the user confirms, even after bullseye, when the change was not in the agreed design.

- 2026-11-02 (builder): I overwrote the architect's tasks/state.md with a shell heredoc because my earlier `ls` was stale (the file appeared after it). Recovered from the git index. Rule: before creating any file with a shell redirect, `git status --short <path>` or `ls` it in the same command; prefer the Write tool (which refuses to overwrite an unread file) for anything that might exist.
- 2026-11-02 (builder): a long multi-heredoc bash command failed to parse as a whole and created nothing. Rule: write source and config files with the Write tool; keep bash for running things.
- 2026-11-02 (builder): mutation-testing a file with `git checkout --` silently reverted an uncommitted edit to the same file (the SQL fix for fallback eligibility) and I only noticed from `git status`. Rule: commit every change before starting mutation tests; restore mutations from a copy or from a clean commit, then check `git status` is empty afterwards.
- 2026-11-02 (builder): "\n" inside a Python snippet in a bash heredoc turned into a real newline in the written source, twice. Rule: do multi-line string edits with the Edit tool, not python-in-bash.
- 2026-11-02 (reviewer/builder P3): rerunning a stage regenerated a committed report and wiped the previous builder's hand-written eyeball verdicts. Rule: before rerunning a stage that writes a docs/ report holding hand judgements, copy the report aside and restore or merge it afterwards; say in the report which numbers changed.
- 2026-11-02 (builder P4): mutation-testing by rewriting a file from Python in text mode on Windows restored the content with CRLF endings, so git showed the file modified with an empty diff. Rule: restore mutated files with `git checkout -- <file>` from a clean commit (not by writing the saved string back), then check `git status --short` is empty.
- 2026-11-04 (builder P6): a background shell chain (ingest, resolve, score) died with the session that started it, leaving scores.parquet written but score_meta.json and the report missing, and no `done` marker. Rule: after a session break, trust a stage only if its last artefact (the meta file) and its completion marker exist; otherwise rerun it whole. Also, a `( cmd ) &` inside a run_in_background call reports the wrapper as finished at once; use `nohup bash -c` plus a marker file and wait on the marker.
- 2026-11-04 (builder P6): python-in-bash string replaces on this repo's CRLF files failed their asserts after a partial write. Rule: detect the file's newline first and convert the pattern, or use the Edit tool; assert before writing, never between two writes.
- 2026-11-04 (builder P5.1): the user saw the overview tiles as misaligned: only 2 of 4 labels had a swatch, so the text started at different x, and a tag made 1 tile taller. Rule: a row of same-role components gets an identical structure (same icon slot, same number of lines, tags pinned in the header), checked with a zoomed screenshot of the row before calling the design done.
- 2026-11-04 (builder P5.1): a CSS rule on `.field > label` also matched chip labels inside the same fieldset and zeroed their padding, which looked like clipped text. Rule: scope form-label rules away from component labels (`:not(.chip)`), and measure element boxes in the browser when something looks clipped instead of guessing.
- 2026-11-04 (builder P5.1): `docker build` in this OneDrive repo fails on reparse-point files. Rule: build from `git archive <sha>` extracted outside OneDrive; it also pins the image to a commit.
- 2026-11-04 (builder P6): a test took "the first scored directory under SIS_DATA" as the real file; once the synthetic file existed it picked that one and passed only because the first synthetic file happened to be within the 5 percent tolerance. Rule: when a new kind of directory or table appears under SIS_DATA, grep the tests for globs over SIS_DATA and make each one skip it; do not accept a pass that depends on which directory sorts first.
- 2026-11-04 (builder P6): an entity-grain perturbation looked like 90 percent recall because the truth counted every entity a shared banner is attributed to as perturbed. Rule: when the unit of a perturbation is not the unit of the metric, record both in the truth file (chosen vs touched) and report each; a metric over the wrong denominator reads as a defect in the thing being tested.
